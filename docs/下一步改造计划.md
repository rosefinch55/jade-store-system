## 阶段二：预约字段修正 + 限流落库

### 2.1 为什么要改

`t_reservation.expect_slot` 现在是 `VARCHAR(64)` 存 `"2026-10-24 15:00"`：

1. 类型不安全，历史自由文本（「2077年」）混在里面，只能靠 Java 侧 try/catch 解析
2. 范围查询（今天有几个预约、未来三天的排期）只能字符串比较或全表读出来在内存筛
3. 时段唯一性无法交给数据库保证，现在是「先查再插」，两个并发请求可以同时通过

### 2.2 表结构改动

```sql
ALTER TABLE t_reservation
  MODIFY expect_slot DATETIME NOT NULL COMMENT '到店时间（半小时对齐）',
  ADD COLUMN ip VARCHAR(45) NULL COMMENT '提交来源 IP（限流与审计）' AFTER phone,
  ADD KEY idx_resv_slot (expect_slot),
  ADD KEY idx_resv_ip (ip);
```

再加两个**函数唯一索引**，用「待确认时才有值」实现部分唯一索引（MySQL 8.0.13+）：

```sql
ALTER TABLE t_reservation
  ADD UNIQUE KEY uk_resv_slot_active
      ((CASE WHEN status = '待确认' THEN expect_slot END)),
  ADD UNIQUE KEY uk_resv_goods_active
      ((CASE WHEN status = '待确认' THEN goods_id END));
```

含义：状态为「待确认」时，同一时段只能有一条、同一货品只能有一条；一旦改成「已到店/已取消/已失效」，索引值为 NULL，互不冲突。**并发的时段抢占由数据库兜底，不再依赖先查后插。**

### 2.3 配套改动

- 过期不再只在内存判断：提交前先把「待确认且到店时间 +60 分钟已过」的记录 `UPDATE status='已失效'`（新增状态值），索引随之释放
- 状态枚举从「待确认|已到店|已取消」扩为四值，类注释与文档同步
- 数据迁移：先备份表，再删除无法解析的历史行（现存 2 条均为测试垃圾），可解析的行转 DATETIME
- 代码：`parseSlot` 只保留给兼容用；查询改 `expect_slot > ?` 走索引

### 2.4 限流规则（三档，落库）

用新增的 `ip` 列直接查库，去掉内存 `ConcurrentHashMap`。

**第一档：当前占用（同时最多 3 条）**

```sql
SELECT COUNT(*) FROM t_reservation
 WHERE ip = ? AND status = '待确认' AND expect_slot > NOW() - INTERVAL 60 MINUTE;
```

只算「待确认且未过期」：客户到店看完（已到店）、主动取消、过期失效，都立刻释放名额，不再占用。

**第二档：历史违约（累计超 10 次拉黑）**

到店时间过了仍未到店的预约，状态改为「已失效」，视为一次违约：

```sql
SELECT COUNT(*) FROM t_reservation
 WHERE ip = ? AND status = '已失效' AND exempt = 0;
```

超过 10 次，拒绝新预约，提示「检测到多次预约未到店，请联系门店解除限制」。违约与占用是两套计数，互不抵消。

**第三档：门店手动解除**

入口：管理端「客户档案」下加一个「预约限制」页签，只有老板（UC-12）可见。
列表列：IP、违约次数、最近一次违约时间、当前是否被限制。

| 交互 | 行为 |
|---|---|
| 点「解除」 | 把该 IP 当前所有 `已失效` 记录的 `exempt` 置 1，并写 `exempt_by`（操作人）与 `exempt_at` |
| 二次确认 | 弹确认框「解除后该 IP 可重新预约，历史违约记录保留但不再计数」 |
| 解除后 | 计数从 0 起算；同一 IP 再累计超 10 次，会再次被限制 |
| 不提供 | 删除记录、改历史违约次数——一律不允许，留痕优先 |

```sql
UPDATE t_reservation
   SET exempt = 1, exempt_by = ?, exempt_at = NOW()
 WHERE ip = ? AND status = '已失效' AND exempt = 0;
```

被限制的客户在客户侧看到的文案：「检测到多次预约未到店，请联系门店解除限制」，同时把门店电话显示出来——不能让客户无处可去。

### 2.5 字段与状态变更汇总

| 项 | 现状 | 改后 |
|---|---|---|
| `expect_slot` | `VARCHAR(64)` 存字符串 | `DATETIME`，半小时对齐 |
| `ip` | 无 | `VARCHAR(45)`，可空（历史数据补不了） |
| `exempt` | 无 | `TINYINT` 默认 0，门店解除时置 1 |
| `exempt_by` / `exempt_at` | 无 | 解除操作人与时间，留痕用 |
| `status` | 待确认/已到店/已取消 | 增加「已失效」 |
| 索引 | goods_id | 加 `expect_slot`、`ip` 普通索引，加两个「仅待确认生效」的函数唯一索引 |

### 2.6 文档影响

`chapter4` 的「预约看货表的字段说明」（`tab:f-t-reservation`）：改 `expect_slot` 类型、加 `ip`、`exempt`、`exempt_by`、`exempt_at` 四行、状态枚举补「已失效」。**表数量不变、ER 图与分析类图不动**，只需重编 PDF（当前 141 页，预计不变）。
