## 关于微信小程序

设计文档把外部协同端定为微信小程序，代码在 `miniprogram/`，九个界面（浏览货品、预约看货、查看调货价、预定、出让申请、预约上门、加工任务、提交完工、查询预约）都已实现。但**它无法直接交给别人扫码使用**，原因有两条，都不是代码问题：

1. **没有备案域名**。小程序线上版只允许请求已备案的 HTTPS 域名，不能是 IP 加端口。服务器现在用公网 IP 直连，微信的域名校验这一关就过不去。
2. **证书不受信任**。服务器用的是自签证书（无域名时无法申请免费受信任证书），微信内置浏览器会直接拦截，连“继续访问”都不给点。

第三条是平台规则：小程序未发布时，只有开发者本人和体验成员（上限 15 人）能打开，公开发布则需要上面两条都满足，再过平台审核。

所以演示走两条路，界面与功能一一对应：

- **客户侧与外部协同**：用 H5 版本，也就是上面的 `mini.html` 与 `external.html`。同一套后端接口、同一套校验规则，扫码即用，不需要登录也能看货。
- **小程序本体**：在微信开发者工具里导入 `miniprogram/` 目录即可本地运行模拟器，供现场演示；若要让评审人自己打开，需在公众平台把对方加为体验成员，并在小程序内打开调试模式。

将来补齐备案域名后，把 `utils/api.js` 里的 `BASE` 换成该域名、在公众平台配置 request 合法域名，小程序即可发布，业务代码不需要改动。

## 本地启动

```bash
# 1. 数据库（假设 MySQL 已在跑）
mysql -uroot -p < docs/schema.sql
mysql -uroot -p < docs/demo-goods.sql
mysql -uroot -p < docs/demo-goods-image.sql
mysql -uroot -p < docs/demo-sales.sql
mysql -uroot -p < docs/demo-business.sql

# 2. 后端（默认连 127.0.0.1:3307；数据源与密钥均走环境变量，没有内置默认口令）
export DB_PORT=3307 DB_USER=root DB_PWD=你的数据库口令
cd server && mvn spring-boot:run

# 3. 打开
open http://127.0.0.1:8080
```

环境变量：

| 变量 | 必填 | 说明 |
|---|---|---|
| `DB_PORT` / `DB_USER` / `DB_PWD` | 是 | 数据源；口令不再有仓库内默认值 |
| `JADE_JWT_SECRET` | 正式部署必填 | 令牌签名密钥，≥32 字节；仓库默认值只供演示 |
| `JADE_JWT_ENC_SECRET` | 可选 | 载荷加密密钥；留空由签名密钥派生 |
| `JADE_JWT_EXPIRE_HOURS` | 可选 | 令牌有效期，默认 8 |
| `MYBATIS_LOG` | 可选 | 设为 `org.apache.ibatis.logging.stdout.StdOutImpl` 才打印 SQL，默认关闭 |

## 关键设计决定

**一、公开接口独立前缀**

客户侧免登录接口统一在 `/api/public/**` 下。拦截器只配一条「放行该前缀」，其余接口默认要求登录——包括没写权限注解的接口，避免漏配。

**二、浏览接口在 DTO 层裁价格**

`/api/public/goods` 的响应里没有 `price`、`cost`、`min_price`、`transfer_price` 任何一项。前端隐藏字段防不住抓包，服务端不给才是真的不给（UC-09 设计约束）。

**三、逾期不落库**

分期计划的 `status` 只写「未还」和「已结清」，逾期由查询时算 `next_due_date < CURDATE() AND paid_amount < 总额`。避免每天跑批改状态。

**四、编号用时间戳而非流水号**

`CJ20261023051234` 这样的格式，前 2 位是业务类型，中间是时间，末 2 位随机。不用「查当日最大序号 +1」——并发下两个请求会拿到同一个最大值，撞唯一索引直接 500。

**五、调货金额不固化**

`t_transfer` 没有金额字段，结算时按 `COALESCE(transfer_price, min_price)` 实时取。代价是货品调价后历史结算金额会失真，已在 `specs/004-transfer` 记为差异。

## 已知限制

| 项 | 说明 |
|---|---|
| 前端是单页 HTML | 不是 Vite 工程，用 CDN 版写法 + 本地依赖。功能完整但不利于多人协作 |
| 客户侧与外部端各有 H5 与小程序两套 | H5 自适应手机与电脑，扫码即用；小程序在 `miniprogram/`，12 页，已建应用卡可预览，正式发布受制于备案域名（见上一节） |
| 证书是自签的 | 端口已跑 HTTPS，但无域名只能用自签证书，浏览器首次会提示来源不明，微信内置浏览器直接拦截。换用受信任证书只需换 keystore |
| 外部端与柜台端共用一套样式代码 | 三端各自一个 HTML，设计令牌重复了一份，改配色要同步三处 |
| 分期逾期天数按自然日 | 未考虑节假日顺延 |
| 图片是朋友圈缩略图 | 中位 154px，列表够用，详情页放大会糊 |

## 上线前检查清单

演示环境用自签证书、默认密钥、放开跨域，都是为省事；正式上线前这三项必须处理。

1. **换 JWT 密钥**。`JADE_JWT_SECRET` 与 `JADE_JWT_ENC_SECRET` 用随机 32 字节以上，经 `run-app.sh` 的环境变量注入，不要沿用仓库默认值——默认值公开可查，任何人都能照着伪造令牌。
2. **收敛 CORS**。`WebConfig` 现在是任意来源 + 允许凭据。域名确定后改成白名单（门店域名 + 管理端域名），其余一律拒绝。
3. **换受信任证书**。自签证书浏览器首次会告警，微信内置浏览器直接拦截；有域名后用 Let's Encrypt 或云厂商证书替换 `deploy/tls` 下的 keystore，`run-app.sh` 不用改。

按钮级权限（菜单已按权限裁剪、按钮未置灰）按设计接受：点击越权操作由接口返回 403 兜底，不另做前端禁用。
