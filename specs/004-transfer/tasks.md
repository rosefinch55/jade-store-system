# 任务清单：同行往来

## 阶段一：数据补全

- [ ] **T001 造出让申请演示数据**
  `t_transfer_apply` 当前为空。造 12 条：8 条待审核、2 条已通过、2 条已驳回（带回审核意见），供应商从 22 个里取，`out_type` 三种都要有。
  *验收*：`SELECT status, COUNT(*) FROM t_transfer_apply GROUP BY status` 三种状态都有。

- [ ] **T002 补调货价的货品**
  `t_goods.transfer_price` 当前大部分为空。给 272 件「调货」来源的货品按 `min_price × 0.6` 回填，让价目页有货可查。
  *验收*：`SELECT COUNT(*) FROM t_goods WHERE status='在柜' AND transfer_price IS NOT NULL` ≥ 200。

## 阶段二：后端商户与供应商

- [ ] **T003 商户价目 `GET /api/merchant/price-list`**
  只返回在柜且 `transfer_price` 非空的货品，支持类别与关键词筛选。
  *验收*：AC-01、AC-03 通过；销售调该接口返回 403（AC-02）。

- [ ] **T004 供应商提交申请 `POST /api/supplier/applies`**
  必填校验、`outType` 三选一、生成 `CR` 前缀编号。
  *验收*：AC-04、AC-05 通过。

- [ ] **T005 供应商查自己的申请 `GET /api/supplier/applies`**
  只返回本账号提交的，带状态与审核意见。
  *验收*：换一个供应商账号登录，看不到别人的申请。

## 阶段三：后端审核

- [ ] **T006 待审核列表 `GET /api/transfer-applies?status=`**
  按提交时间升序，销售可读、老板可审。
  *验收*：列表顺序正确；销售视角没有「审核」按钮（后端也拦）。

- [ ] **T007 审核 `POST /api/transfer-applies/{id}/audit`**
  驳回必须填原因；非老板返回 403；已审过的返回 409。
  *验收*：AC-06、AC-07、AC-08 通过。

## 阶段四：后端调货

- [ ] **T008 登记调货 `POST /api/transfers`**
  校验商户类型为「同行商户」、货品非重复调货；插记录 + 改货品状态 + 写流水，同一事务。
  *验收*：调出后货品变「已调出」，公开列表里消失。

- [ ] **T009 改调货状态 `PUT /api/transfers/{id}/status`**
  只允许「已售」「已退回」；改「已售」时货品同步变「已售」，改「已退回」时回「在柜」。
  *验收*：AC-09 通过。

## 阶段五：后端结算

- [ ] **T010 未结算清单 `GET /api/settlements/pending`**
  按商户列未结算记录，金额取 `COALESCE(transfer_price, min_price)`，算 `overdueDays`。
  *验收*：清单金额合计与逐条相加一致。

- [ ] **T011 批量结算 `POST /api/settlements/batch`**
  多条一起结，逐条插结算单、把调货记录置已结算；任一条失败整体回滚。
  *验收*：AC-10、AC-11 通过；故意传一条已结算的，全部回滚。

- [ ] **T012 结算历史 `GET /api/settlements`**
  按商户、时间筛选，`settle_type=调货`。
  *验收*：能查到 T011 生成的单据。

## 阶段六：前端

- [ ] **T013 商户调货价目页（小程序）**
  卡片流，显示货品图、品名、尺寸、调货价；类别筛选 + 关键词搜索。
  *验收*：搜「手镯」只出手镯，价格显示调货价不是零售价。

- [ ] **T014 供应商出让申请页（小程序）**
  表单：类型三选一、品名、数量、期望价、描述、传图。提交后显示申请编号与状态。
  *验收*：提交成功，列表里能看到自己的申请与审核结果。

- [ ] **T015 待审核申请页（老板端）**
  列表 + 详情抽屉，通过/驳回两个按钮，驳回时弹原因输入框。
  *验收*：AC-06 的拦截在页面上体现（不填原因提交不了）。

- [ ] **T016 调货记录页（老板端）**
  列表按商户分组，显示方向、货品、状态、是否已结算；可改状态。
  *验收*：改「已退回」后货品回到在柜。

- [ ] **T017 台账结算页（老板端）**
  选商户 → 列未结算 → 勾选多条 → 显示合计 → 确认结算。
  *验收*：AC-10、AC-11 通过；结清后再进来提示「已结清」。

## 与其他 feature 的交界

- 依赖 `001-goods` 的货品状态机：「已调出」「在柜」「已售」三态流转
- 与 `005-consign` 共用 `t_settlement`，靠 `settle_type` 区分，两边都要实现按类型查询
- 与 `002-sale` 的交界：调货货品售出后走成交登记，成交价可能高于调货价，差额归本店
