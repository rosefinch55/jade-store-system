# 功能规格：账号与基础数据

**功能分支**：`000-base`
**需求来源**：分析设计文档 §2.3 UC-08 登录、UC-12 开通外部账户、UC-07 维护基础数据
**状态**：Draft

## 范围

登录验证、账号开通与停用、角色与权限分配、三类基础数据的维护。

货品、客户、成交等业务数据不在此处，见各业务 feature。

## 功能需求

| 编号 | 需求 | 来源 |
|---|---|---|
| FR-001 | 用户名 + 口令登录，口令以 bcrypt 加密保存，禁止明文 | UC-08 质量需求 |
| FR-002 | 连续 5 次口令错误，账号锁定 10 分钟，提示联系老板解锁 | UC-08 业务规则① |
| FR-003 | 登录成功返回角色集合与权限集合，菜单按权限生成、按钮按权限置灰 | UC-08 后置条件 |
| FR-004 | 不做自助注册，所有账号由老板开通 | UC-08、UC-12 设计约束 |
| FR-005 | 老板可开通账号并分配角色（可多选），可停用；停用后无法登录 | UC-12 基本路径 |
| FR-006 | 用户名全局唯一 | UC-12 扩展 2a |
| FR-007 | 基础数据分三类：来源方（供应商/加工师傅/同行商户）、鉴定机构、货品类别 | UC-07 基本路径 |
| FR-008 | 名称在同一类别内唯一，跨类别可重复 | UC-07 扩展 3a |
| FR-009 | 被业务数据引用的基础数据不可物理删除，只能停用 | UC-07 业务规则① |
| FR-010 | 外部账号首次登录可修改口令 | UC-12 业务规则③ |
| FR-011 | 五个角色各持一组权限，映射见报告 §4.4 权限矩阵 | 权限矩阵 |
| FR-012 | 权限点与功能用例一一对应，编码取 UC 编号 | 报告 §4.4 |

## 验收标准

| 编号 | 条件 | 预期 | 对应 |
|---|---|---|---|
| AC-01 | 输入正确用户名与口令 | 返回 token 与用户信息，含角色与权限列表 | FR-001、FR-003 |
| AC-02 | 输入错误口令 | 返回 401，提示用户名或口令错误 | FR-001 |
| AC-03 | 同一账号连续错 5 次 | 第 5 次后返回 423，账号锁定 10 分钟 | FR-002 |
| AC-04 | 锁定期间用正确口令登录 | 仍返回 423，提示剩余锁定时间 | FR-002 |
| AC-05 | 停用账号登录 | 返回 403，提示账号已停用 | FR-005 |
| AC-06 | 老板开通账号，用户名已存在 | 返回 409，提示更换用户名 | FR-006 |
| AC-07 | 老板给一个账号分配两个角色 | 登录后两个角色的权限取并集 | FR-005、FR-011 |
| AC-08 | 销售访问老板专属接口（如开通账号） | 返回 403 | FR-011 |
| AC-09 | 新增来源方，同类别下名称重复 | 返回 409 | FR-008 |
| AC-10 | 删除已被货品引用的来源方 | 返回 409，提示只能停用 | FR-009 |
| AC-11 | 停用某个来源方后新建货品 | 下拉列表中不再出现 | FR-009 |

## 性能与约束

- 登录验证 1 秒内反馈（UC-08 质量需求）
- 新增一条基础数据不超过 3 次操作（UC-07 质量需求）
- 开通一个账号不超过 3 次操作（UC-12 质量需求）

## 边界情况

- 老板自己的账号不允许停用，避免无管理员可用
- 账号锁定按用户名计数，不按 IP；老板解锁即清零计数
- 基础数据停用后，历史业务记录仍显示原名称，不做级联改名
- 类别改名后，历史货品的类别显示同步更新（类别是外键引用，非冗余存储）

## 与文档的差异

**一处未落地的业务规则**：UC-07 业务规则②要求「供应商类型区分玉料/成品/回流」，但 `t_source_party` 只有 `party_type`（供应商/加工师傅/同行商户）一个字段，没有二级细分列。

当前处理：该细分信息暂存 `remark`，不做筛选。若后续要按细分类型统计，需给表加一列 `supply_kind`，届时走一次 schema 变更。

原因记录在此，避免开发时误以为漏实现。

**补充（2026-10-26 复核，对应代码审查报告 §三 B 组）**

B14｜被锁账号没有解锁入口。规格 FR-002 要求老板可解锁，实现只依赖 10 分钟自动过期，没有解锁接口。处置：接受现状，账号锁定按"等 10 分钟"处理；频繁误锁时再补一个 `POST /users/{id}/unlock`。

B15｜来源方不能停用。FR-009 要求可停用，`t_source_party` 没有 `status` 列。处置：接受现状——有引用的来源方不允许删除，无引用可直接删；停用机制留待需要时再加列。

B16｜外部账号改密只有接口没有入口。改密接口 `PUT /auth/password` 已通，三个前端都没有修改口令的界面，初始口令只能由门店口头告知。处置：接受现状，改密由门店在柜台端代改；补一个入口属增强项。
