# 功能规格：成交与账务

**功能分支**：`002-sale`
**需求来源**：分析设计文档 §2.3 UC-01 登记成交、UC-03 登记退货、UC-24 登记分期计划、UC-25 记录分期还款、UC-19 登记货款记录、UC-06 查看销售与周转统计
**依赖**：`000-base`（登录与权限）、`001-goods`（货品档案与状态机）
**状态**：Draft

## 范围

成交登记、退货、分期计划与还款、货款收付记录、销售与周转统计。

调货结算、寄售结算各自独立成 feature；本处只做「成交时是否分期」「退货冲减统计」这两处与之相关的联动。

## 性能与约束

- 一次成交登记不超过 4 次操作、10 秒内完成，提交后 1 秒内反馈（UC-01 质量需求）
- 一次退货登记不超过 3 次操作（UC-03）
- 一次还款登记不超过 2 次操作（UC-25）
- 统计查询 2 秒内反馈（UC-06）
- 货款当面收付，不接在线支付接口（UC-01、UC-03 设计约束）
- 柜台端部署在门店本地网络，外部角色走小程序

## 边界情况

- 散客成交不关联客户，统计的「销售客户数」按有客户记录的成交去重计算
- 定金成交后客户违约不取货，当前无专门流程：由退货（7 天内）或人工调整处理，见「与文档的差异」
- 一件货品退回后再次售出，产生新的成交记录，原成交保留为「已退货」状态，不删除
- 分期计划的期数由店内核定，系统不设上限
- 货款记录作废需保留原记录痕迹，见「与文档的差异」

## 与文档的差异

**一、货款与分期缺「作废」字段**

UC-19 业务规则③要求「记录只增不改，登记错误时作废重录」，UC-25 也提到结清归档。但 `t_payment`、`t_installment` 没有 `voided`、`void_reason`、`void_by` 之类字段。

当前处理：作废通过在 `remark` 里写标记实现，不改表结构。代价是无法用 SQL 直接筛出「未作废」的记录，统计时要靠字符串判断。

若后续作废操作变多，建议加 `voided TINYINT(1)` 与 `void_at`，届时走一次 schema 变更。

**二、定金违约无流程**

UC-01 只规定定金成交标记「已订」，没写客户不取货怎么办。当前按退货路径处理，但退货要求 7 天内且原因限真假/质量，定金违约不符合这个条件。

留待业务确认：定金不退、转为其他货品、或另有约定。

**补充（2026-10-26 复核，对应代码审查报告 §三 B 组）**

B2｜按来源渠道汇总成交与贡献客户榜（FR-027）未实现。后端没有对应接口，前端也没有模块。处置：标注为未实现，不进本期验收；如要补，按客户来源渠道分组聚合即可，一天工作量。

B3｜货款金额与关联单据一致性（FR-022／AC-15）未校验。任意金额都能入账。处置：接受现状，靠人工对账；若要加校验，按 `biz_type` 取关联单金额比对，超出阈值拒绝。

B11｜退货与定金的口径。退货不冲减"成交客户数"，定金成交按全价计入销售额。处置：接受实现口径，验收时按此理解；两处都在统计页脚注了说明。

B12｜周转天数按最低售价加权、成交即计，规格写的是"货品总金额"且含收款环节。处置：接受实现口径（成本口径更保守），前端页面已标注口径。
