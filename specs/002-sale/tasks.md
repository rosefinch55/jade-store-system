# 任务清单：成交与账务

## 阶段一：数据准备

- [ ] **T001 造演示成交数据**
  679 件货品当前全部「在柜」，`t_sale` 为空。需要造 40–60 笔成交，覆盖：全款、定金、退货、分期未还、分期已结清、逾期六种情况，时间分散在最近 3 个月，让统计和周转有数可算。
  *验收*：`SELECT COUNT(*) FROM t_sale` ≈ 50；`t_goods` 中「已售」「已订」各占一部分；`t_installment` 三种状态都有。

## 阶段二：后端成交

- [ ] **T002 成交实体与 Mapper**
  `Sale`、`SaleReturn`、`Installment`、`Payment` 四个实体，字段严格对齐 `data-model.md`。
  *验收*：`saleMapper.selectById(1)` 能查出数据。

- [ ] **T003 成交登记 `POST /api/sales`**
  四步校验按 `contracts/api.md` 的顺序实现；插成交、改货品状态、写流水同一事务。
  *验收*：AC-01~AC-05 全通过；对「已售」货品再成交返回 409。

- [ ] **T004 底价授权**
  成交价低于最低售价时，必须带老板 id 与授权说明，否则 422。授权信息记在成交记录备注里。
  *验收*：不带授权返回 422；带授权成功，且成交记录能查到授权人。

- [ ] **T005 退货 `POST /api/sales/{id}/returns`**
  校验 7 天期限、原因范围、未退过；退货后货品回「在柜」、写流水、当月统计冲减。
  *验收*：AC-06~AC-09 全通过。

## 阶段三：后端分期

- [ ] **T006 建分期计划 `POST /api/sales/{id}/installment`**
  按成交价与期数算每期应还，末期吸收四舍五入尾差，保证各期之和等于成交价。
  *验收*：12800 分 6 期，各期之和恰好 12800.00；重复建返回 409。

- [ ] **T007 还款 `POST /api/installments/{id}/payments`**
  金额不超余额，累加已还、推进到期日、结清置状态。
  *验收*：AC-11、AC-12 通过；结清后再还返回 409。

- [ ] **T008 逾期计算**
  查询时按 `next_due_date < CURDATE() AND paid_amount < 总额` 判定，返回 `displayStatus` 与 `overdueDays`，不改库里的 `status`。
  *验收*：AC-13 通过；把系统日期调到到期日后，原「未还」显示为「逾期」。

## 阶段四：后端货款与统计

- [ ] **T009 货款记录 `POST /api/payments`**
  四种业务类型、四种单据类型、金额与单据一致校验。
  *验收*：AC-15 通过。

- [ ] **T010 货款作废**
  `POST /api/payments/{id}/void`，按 `remark` 写 `VOID:` 前缀实现（临时方案，接口形态留给后续换字段）。
  *验收*：作废后统计不再计入该笔。

- [ ] **T011 销售统计 `GET /api/stats/sales`**
  按 `data-model.md` 的三条 SQL 口径实现；主力是销售额（退货冲减）与客户数（去重、散客不计）。
  *验收*：AC-16 通过；手工从 SQL 算一遍，结果与接口一致。

- [ ] **T012 周转统计 `GET /api/stats/turnover`**
  加权天数用 `min_price` 加权，附最慢 10 件货品。
  *验收*：抽样 5 件手算加权天数，与接口一致。

## 阶段五：前端

- [ ] **T013 成交登记页**
  扫条码或输编号带货品信息、显示最低售价、填成交价与支付方式、选客户（可空）。低于底价时弹出授权录入。
  *验收*：完整走一笔全款成交，10 秒内完成。

- [ ] **T014 退货页**
  从成交详情进入，显示成交日期与剩余可退天数，原因二选一。
  *验收*：超过 7 天的成交，退货按钮置灰并提示超期。

- [ ] **T015 分期管理页**
  列表带逾期高亮、剩余应还、下一期到期日；点开可还款。
  *验收*：逾期记录排在前面并用红色标记。

- [ ] **T016 货款台账页**
  四种业务类型分 tab，按时间倒序，显示收付方向。
  *验收*：切换 tab 筛选正确。

- [ ] **T017 统计页**
  时段切换（月/季/年）、销售额与退货冲减分列、客户数、加权周转天数、渠道分布、核心客户。
  *验收*：三个指标与 T011、T012 的接口返回一致。

## 与其他 feature 的交界

- 依赖 `001-goods` 的货品状态机：成交改「已售/已订」、退货回「在柜」
- 依赖 `000-base` 的权限：成交与退货给销售，货款与统计只给老板
- 与 `004-transfer`、`005-consign` 的交界在 `t_payment`：调货货款、寄售货款由那两个 feature 写入，本处只提供接口
