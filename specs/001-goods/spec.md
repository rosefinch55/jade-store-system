# 功能规格：货品档案

**功能分支**：`001-goods`
**需求来源**：分析设计文档 §2.3 UC-02 登记货品入库、UC-07 维护基础数据、UC-26 查看库存流水
**状态**：Draft

## 范围

逐件建立货品档案、按条件检索、修正档案、查看状态流水。

成交登记、送检、调货、寄售结算各自独立成 feature，不在此处。

## 功能需求

| 编号 | 需求 | 来源 |
|---|---|---|
| FR-001 | 每件货品生成唯一编号，不可修改、不可复用 | UC-02 业务规则① |
| FR-002 | 一次入库可提交多件，按件生成独立档案，共用同一入库批次 | UC-02 扩展 3a |
| FR-003 | 来源类型限定为 采购、回收、调货、加工完工、寄售 五种 | UC-02 字段列表 |
| FR-004 | 来源类型为调货时，成本可空，记录来源商户与往来 | UC-02 业务规则③ |
| FR-005 | 来源类型为回收时，按回流作价确定成本 | UC-02 业务规则② |
| FR-006 | 来源类型为加工完工时，按料加工合计入成本 | UC-02 业务规则④ |
| FR-007 | 来源类型为寄售时，寄售价作为成本，同时作为结算依据 | UC-02 业务规则⑤ |
| FR-008 | 状态限定为 在柜、已送检、预留、已售、已订、已调出、代销中、待处理 八种，初始为在柜 | 报告 §3.3 状态机 |
| FR-009 | 状态变更必须由业务动作驱动，不提供直接改状态的操作 | 状态机完整性 |
| FR-010 | 每次状态变更写入流水，记录变更前后状态、关联单据、经手人、时间 | UC-26 |
| FR-011 | 已售货品不允许修改档案字段 | 数据一致性 |
| FR-012 | 列表支持按状态、类别、编号或品名关键词筛选，按入库时间倒序分页 | UC-02 后置条件 |
| FR-013 | 类别被货品引用时不允许删除 | 删除策略 RESTRICT |
| FR-014 | 首页上部与推荐位只展示 `is_featured=1` 的货品（94 件，图与货品同源） | 演示规则 |
| FR-015 | 其余货品（585 件）在全部库中可查可筛，但不进推荐位、不参与首页排序权重 | 演示规则 |

## 验收标准

| 编号 | 条件 | 预期 | 对应 |
|---|---|---|---|
| AC-01 | 录入一件和田玉手镯，必填齐全 | 生成唯一编号，状态「在柜」，入库时间为当前时间 | FR-001、FR-008 |
| AC-02 | 同一批次提交 5 件珠串 | 5 条独立档案，编号各不相同，共用同一批次 | FR-002 |
| AC-03 | 来源类型选调货且不填成本 | 保存成功，成本为空，来源商户已记录 | FR-004 |
| AC-04 | 来源类型选回收但不填成本 | 拒绝，提示成本必填 | FR-005 |
| AC-05 | 来源类型选寄售，填寄售价 8000 | 成本与结算依据均为 8000 | FR-007 |
| AC-06 | 按状态「在柜」+ 类别「翡翠」筛选 | 只返回同时满足两条的货品，按入库时间倒序 | FR-012 |
| AC-07 | 输入编号片段查询 | 返回匹配货品 | FR-012 |
| AC-08 | 50 条数据翻到第 3 页 | 每页条数与总数正确 | FR-012 |
| AC-09 | 修改在柜货品的最低售价 | 价格更新，编号与状态不变 | FR-011 |
| AC-10 | 修改已售货品 | 拒绝，提示已售不可改档 | FR-011 |
| AC-11 | 查看刚入库货品的流水 | 一条记录，变更前为空，变更后为「在柜」 | FR-010 |
| AC-12 | 删除已被引用的类别 | 拒绝，提示先转移货品 | FR-013 |
| AC-13 | 打开首页 | 上部推荐区只出现 `is_featured=1` 的货品，数量不超过 94 | FR-014 |
| AC-14 | 在全部库中按器型筛选 | 585 件非精选货品同样能被查到，但不出现在首页推荐区 | FR-015 |

## 性能与约束

- 单件建档耗时不超过 30 秒（UC-02 质量需求）
- 按编号查询，10 万条以内 1 秒内返回
- 与纸质台账并行运行一个月，双轨核对无误后停用台账（UC-02 设计约束）

## 边界情况

- 同批次多件但克重不同，逐件录入，不提供批量填充
- 图片上传失败时档案仍可保存，图片字段留空事后补传
- 手串拆成单颗出售，按重件规则另建档案，原货品置为「待处理」
- 调货调入的货品在结算时以调货价回填成本，不回填则周转统计缺少该件口径

## 与文档的差异

需求来自 UC-02、UC-07、UC-26 三条规约。UC-02 原文只讲建档，本规格把「检索、改档、查流水」一并纳入，因为这三件事在实现上共用同一批表和同一个服务，拆开反而增加成本。
