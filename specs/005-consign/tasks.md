# 任务清单：寄售结算

## 阶段一：数据补全

- [ ] **T001 造可结算的寄售数据**
  现有 68 条寄售明细的货品全是「在柜」，没有可结算的。挑 12 件寄售货品造成交记录（走 `t_sale`，货品变「已售」），其中 6 件已结算、6 件待结算。
  *验收*：`SELECT settle_status, COUNT(*) FROM t_consignment_item GROUP BY settle_status` 两态都有。

## 阶段二：后端合同

- [ ] **T002 寄售实体**
  `Consignment`、`ConsignmentItem` 两个实体，字段对齐 `data-model.md`。
  *验收*：能查出已有 6 份合同与 68 条明细。

- [ ] **T003 登记合同 `POST /api/consignments`**
  一次提交合同头 + 货品清单；逐件建档（`src_type=寄售`、`cost=consignPrice`）、插明细、写流水，同一事务。
  *验收*：AC-01、AC-02、AC-03 通过；供应商不存在返回 422。

- [ ] **T004 追加货品 `POST /api/consignments/{id}/items`**
  向已有合同加货，校验一件货品只能挂一份未结算明细。
  *验收*：AC-04 通过。

- [ ] **T005 合同详情 `GET /api/consignments/{id}`**
  返回明细、已售件数、已结算件数、待结算金额；`settled` 由明细实时算，不读合同状态。
  *验收*：6 份合同的 `settled` 都算对。

## 阶段三：后端结算

- [ ] **T006 可结算清单 `GET /api/consignments/settleable`**
  筛 `settle_status='未结算' AND t_goods.status='已售'`，按供应商可选过滤。
  *验收*：AC-05 通过（未售出的不出现）。

- [ ] **T007 批量结算 `POST /api/consignments/settlements`**
  三步事务：插结算单、改明细状态、插货款记录；任一条失败整体回滚。
  *验收*：AC-06、AC-07、AC-08 通过。

- [ ] **T008 终止合同 `POST /api/consignments/{id}/terminate`**
  未结算明细的货品改「待处理」；有已售未结算的明细时拒绝终止。
  *验收*：AC-09 通过。

## 阶段四：前端

- [ ] **T009 合同列表页**
  卡片或表格：合同号、供应商、签订日、到期日、件数、已结清标记。
  *验收*：6 份合同都能列出来，已结清的显示「已结清」标签（实时算）。

- [ ] **T010 合同详情页**
  头部合同信息 + 结清进度条；明细表带状态（在柜/已售/已结算）；底部「追加货品」「终止合同」。
  *验收*：点开 JS20260001 能看到 12 件明细与各自状态。

- [ ] **T011 登记合同页**
  供应商下拉、日期、结算方式、货品清单（可增行）。一次提交。
  *验收*：录 2 件寄售货品，提交后货品状态「在柜」、成本=寄售价。

- [ ] **T012 结算页**
  可结算明细列表，勾选多条、显示合计、选结算方式后确认。
  *验收*：AC-06 通过；结算后清单里那几条消失。

## 阶段五：验收

- [ ] **T013 走查 9 条验收标准**
  *验收*：AC-01~AC-09 全通过或差异在案。

## 依赖关系

```
T001 → T002 → T003 → T004 → T005
                        └──→ T006 → T007 → T008
                                        ↓
              T009 → T010 → T011 → T012 → T013
```

T006 依赖 `002-sale` 的成交登记能跑通（寄售货品要先售出）。

## 与其他 feature 的交界

- **与 `002-sale`**：寄售货品的售出走成交登记，本 feature 只处理「售出之后结算」。退货时若明细已结算，无自动回退（见 spec 差异二）
- **与 `004-transfer`**：共用 `t_settlement`，查询时按 `settle_type` 过滤
- **与 `001-goods`**：寄售建档的货品 `src_type='寄售'`、`cost=寄售价`
